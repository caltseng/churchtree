This is a static multi-page site. Older plan documents are historical context,
not evidence that an old renderer, single-set model, or backend is current.

The country-history route `/china-history/` is deliberately separate from the
denomination catalog. Its canonical input is `china-history/data.cjs`; validation
accounts for every H01-H54 research row as a selected record or an explicitly held
row, verifies calendar bounds and evidence references, and rejects structural
lineage relationships. `scripts/build-country-history.cjs` uses the shared
`templates/country-history.html` and each country configuration to project approved
public fields into tracked HTML and `public-data.js`. Only those two outputs and
the shared `country-history/history.css` and `controller.js` are published.
Source research and builder/template inputs remain private to the repository.

The route reuses `timeline-model.js`, `timeline.js` and
`horizontal-timeline.js`, with optional presentation hooks for display lanes,
precise date labels and interval marks. Existing callers retain the denomination
defaults. `historical-dates.js` validates ISO calendar periods and converts dates
to fractional years only at the rendering boundary; the original dates, basis,
testimony and caveats remain in both the generated list and detail profile.
Context/attestation links are navigable text with evidence, not graph lineage.
The progressive HTML list is complete without JS or D3. There is intentionally no
Compact lineage option because this research does not establish a national
institutional genealogy.

`/global-church/` is the country chooser generated by `scripts/build-home.cjs`
from `site.config.json`'s `countryHistories` registry. The release builder runs one
shared country renderer. After preparing editorial data and its validator, adding
a country is one registry entry: card metadata, page description, search example
and last verified event. Optional trusted `scopeDetails` HTML preserves additional
source notices; `showCountryChooser` and `noScript` preserve route-specific copy.
The registry also publishes the two generated route files automatically; no
per-country builder, template or public-file list edits are needed.

`/cambodia-history/` has independent editorial data, validator and tests, sharing
the country builder/template, neutral controller/CSS and the same date/timeline
modules. Every route uses only `COUNTRY_HISTORY_DATA`. The shared
`scripts/validate-country-history.cjs` receives each route's explicit research-ID
roster, retaining China's H01-H54 coverage without cross-country imports.
Cambodia accounts for KH01-KH50, selecting 42 and explicitly holding eight.
The source packet and staging crosswalks are not published; dates, original
summaries, caveats, credit and precise locators are. See its
[handoff](../research/cambodia/handoff.md) and
[coverage register](../research/cambodia/coverage.md).

`/thailand-history/` follows the same contract, with H01-H44 explicitly
accounted for as 40 selected events and four held rows. Its year/month/day
bounds, evidence and provisional claims remain qualified; the 1918-1919
Adventist interval retains the December arrival in prose rather than inventing
a 1919 month. Research/held crosswalks remain outside the artifact. See its
[handoff](../research/thailand/handoff.md) and
[coverage register](../research/thailand/coverage.md).
Syntax checks discover all registered country folders; each country also has
its own validation and browser-test command.
