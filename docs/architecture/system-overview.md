# System overview

Main Branch is a static collection with a generated landing inventory, a D3-based
church-history explorer, and a chapter/section reader. It requires no database,
authentication service or runtime application server. Node is used for building,
validation and browser tests; GitHub Pages serves the resulting static files.

## Pages and shared foundation

- `/`: `templates/home.html` plus `site.config.json` page metadata, generated by
  `scripts/build-home.cjs` into generated, ignored `index.html`.
- `/global-church/`: country chooser from the `countryHistories` registry.
  `/china-history/`, `/cambodia-history/` and `/thailand-history/` keep separate editorial inputs;
  the shared country builder publishes only approved fields and full sourced
  HTML. Country events never enter denomination discovery.
- `/church-history/`: `templates/church-history.html` generates the page; root `explorer.js`
  handles scope, search, selection and compact lineage. `timeline.js` and
  `horizontal-timeline.js` render the two proportional orientations.
- `/westminster/`: `content.json` and `build.cjs` generate a full-text HTML reader;
  `reader.js` enhances navigation. The primary text remains available without JS.
- `theme.css` defines semantic colors; `theme.js` applies the browser's saved
  palette. `theme-controls.css` styles the chooser and `brand.css` shares lockups.
  Palette proposals and the selected logo's fixed colors are separate concerns.
- `scripts/page-shell.cjs` owns the brand markup and shared head/header/footer
  partials. Every published page has a canonical URL, site-name metadata and
  a skip link; the shared skip-link rule is in `theme.css`.

The explorer's broad overview groups traditions. `graph-groups.js` defines curated
historical display groups; these are not new canonical denominations. The pure
`timeline-model.js` computes temporal clusters, grouped relationships and branch
lanes. Narrow time windows reveal records; wide windows collapse nearby records
within appropriate lanes. Node dates are not changed to resolve collisions.
Compact lineage instead uses readable chronological spacing without proportional time.

Profiles render beliefs, formation and continuation, milestones, contextual people,
documents, claim-linked sources and supported successors. They stay beside the graph
on desktop, or move into a native reading sheet below 1100px. The panel is moved back
when the viewport returns to desktop; the canonical record/selection is unchanged.

## Data flow

`data/sets/<set>/notes` + verified sources → canonical set JSON and shared evidence →
`scripts/build-site.cjs` → `dist/data/data.js` → explorer.

Every set has nodes/edges; events and local sources/citations are optional. Shared
sources/citations come from `data/common`. The build discovers sets rather than
hard-coding their names. The legacy PowerShell builder refreshes `data/data.js` for
source preview; the release builder regenerates data directly from canonical JSON.
Tests of the release serve `dist/`, not an old source bundle.

## Release boundary

The build regenerates ignored page outputs, makes a clean `dist/`, copies allowed
root assets and explicit public directories from `site.config.json`, and writes the
custom domain and no-Jekyll marker. Research docs, scripts, templates and Git metadata
are not web assets. Internal references are checked before publishing.

GitHub's required `Build and test` job runs model/guard, desktop/mobile, reader and
landing/theme journeys. Only a passing main build can upload/deploy the Pages
artifact. Protected branches and auto-merge are repository settings/workflows, not
a promise made by a local test. See [deployment](../deployment.md).

## Current limits

Coverage is partial and historical confidence varies; read the data audit. D3 remains
an external CDN runtime dependency. Dense cross-tradition edge routing is heuristic.
Browser emulation is not a substitute for testing actual Safari/touch devices.
Theological-development timelines and the optional reader study layer have their
own plans and must not be presented as already finished merely because files exist.
